## 생산관리

- 하이닉스 1분기 실적 발표 : 제조업 회사가 어떻게 매출이 52조인데 순이익률이 77%가 나올 수 있는지 40조원
- 효율성(Efficiency) : 얼마나 자원을 적게 사용하며 달성했는가?
- 효과성(Effectiveness) : 목표를 얼마나 잘 달성했는가?
- p-value : 귀무가설이 참이라고 가정했을 때 결과가 우연히 발생했을 확률
- 표준오차(SE) : 샘플의 평균이 얼마나 흔들릴 수 있는가에 대한 지표 $$ \text{SE}=\frac{s}{\sqrt{n}}=Var(\bar{X})^\frac{1}{2}=Var(\frac{X_1+\dots+X_n}{n})^\frac{1}{2}=(\frac{1}{n^2}ns^2)^\frac{1}{2}$$
- 결측값 처리방법
	- 삭제
	- 채워넣기 (mean, median, mode, 예측값)
- 이상치 처리방법
	- 데이터가 정규 분포일 때 -> z-score 값 기준으로 처리하는 방법
	- 데이터가 한 쪽으로 skewed 될 때 -> IQR(75%의 값 - 25% 값) : IQR에 1.5 같은 값을 곱한 후에 Q3나 Q1 끝에 더하거나 빼서 바운더리를 쳐주는 기법
	- 다차원 데이터에서는 클러스터링 사용
- A/B testing : A를 했을 때와 B를 했을 때 차이를 구하고 p-value를 통해 그 차이가 유의미한지 확인하는 방법
- 회귀 분석 : 두 변수의 관계를 선형 방정식으로 나타낸 것
- 이동평균법(moving average) : 일정 기간의 값 평균을 구해서 미래 값을 예측하는 것
- 지수평활법(exponential smoothing) : 직전 관측값에 평활 계수를 곱해서 미래 값을 예측하는 것 $$F_{n+1}=\alpha Z_n+(1-\alpha)F_{n} $$

- 생산관리 : 기업의 목표는 돈을 버는 것인데, 생산관리는 Production Planning과 control을 통해 이를 극대화할 수 있게 하는 직무입니다.
	- 주로 KPI 기반의 리포트를 작성해서 정량적으로 분석함
- TQM(Total Quality Management) : 특정 부서만이 아니라 회사 전체가 참여해서 지속적으로 품질을 개선하자
- ABC 분석 : 전체를 중요도에 따라 정렬하고 70%에 속하는 것을 A그룹 20%에 속하는 것을 B, 10%에 속하는 것을 C로 나눈 후에 A부터 집중하여 관리하는 방법

		- UPH(Units Per Hour) : 시간 당 몇 개 units을 생산하는지

## Little’s Law

$$WIP=TH\cdot CT$$

- WIP (work-in-process) : 단위 시간 동안 공정 내 머물러 있는 평균 재고량
- TH (throughput) : 단위 시간 동안 평균 산출량
- CT (cycle time) : 하나의 unit을 생산하는데 걸리는 시간


## Queueing Theory

### Poisson distribution

independent event가 핵심이고 n개 구간에 대해서 각 구간에서 event가 발생할 확률이 p라고 하면 전체 구간에서 기대값이 np가 되고 이를 $\lambda$라고 하면 $p=\frac{\lambda}{n}$으로 둘 수 있음.  

전체 구간에서 event가 k번 발생할 확률은 이항 분포에 의해 $\binom{n}{k} p^{k}(1-p)^{n-k}$이 됨.  

$$\begin{flalign}&=\frac{n(n-1)\dots(n-k+1)}{k!}(\frac{\lambda}{n})^k(1-\frac{\lambda}{n})^n(1-\frac{\lambda}{n})^{-k}\\&=\frac{\lambda^k}{k!}\cdot\frac{n(n-1)\dots(n-k+1)}{n^k}(1-\frac{\lambda}{n})^n(1-\frac{\lambda}{n})^{-k}\\&=\frac{\lambda^k}{k!}\cdot\frac{n(n-1)\dots(n-k+1)}{n^k}(1+\frac{1}{-\frac{n}{\lambda}})^{-\frac{n}{\lambda}\cdot -\lambda}(1-\frac{\lambda}{n})^{-k} \end{flalign}$$

$n\rightarrow\infty$이면 $\frac{\lambda^k\cdot e^{-\lambda}}{k!}$으로 수렴하게 됨.  


### M/M/1 queue

- queue : job과 server로 이루어진 대상으로 server는 job을 받아서 처리하는 과정을 반복함  
- arrival : server가 job을 받는 사건
- departure : server가 job의 처리를 끝낸 사건
- state : 시스템에 포함된 job의 개수
- queue length : 처리 대기 중인 job의 개수

M/M/1 queue는 server가 하나이고 수용 가능한 job 개수 한계가 없으며 arrival process와 departure process가 포아송 분포에 의해 진행(memoryless)되는 시스템. 시점 t에서 state가 k일 때의 확률 $p_k(t)$을 모델링할 수 있음.  

arrival process의 빈도를 $\lambda=np$라고 하고 departure process의 빈도를 $\mu=np^\prime$라고 하면  

$$\begin{flalign}p_k(t+\frac{1}{n})&= p_k(t)\cdot (1-\frac{\lambda}{n})(1-\frac{\mu}{n})+p_{k-1}(t)\frac{\lambda}{n}(1-\frac{\mu}{n})+p_{k+1}(t)(1-\frac{\lambda}{n})\frac{\mu}{n}\\ p_0(t+\frac{1}{n})&=p_0(t)\cdot (1-\frac{\lambda}{n})+p_1(t)(1-\frac{\lambda}{n})\frac{\mu}{n}\end{flalign}$$

이때 좌변을 미분계수 꼴로 변형 해주면 도함수를 얻을 수 있다  

$$\begin{flalign}\frac{p_k(t+\frac{1}{n})-p_k(t)}{\frac{1}{n}}&=p_k(t)(\frac{\lambda\mu}{n} -(\lambda+\mu))+p_{k-1}(t)(\lambda-\frac{\lambda\mu}{n})+p_{k+1}(t)(\mu-\frac{\lambda\mu}{n})\\\lim_{n\rightarrow \infty}\frac{p_k(t+\frac{1}{n})-p_k(t)}{\frac{1}{n}} &= -p_k(t)(\lambda+\mu)+\lambda \cdot p_{k-1}(t)+\mu\cdot p_{k+1}(t)\\&=p^\prime_k(t)\\ p^\prime_0(t)&=-p_0(t)\cdot \lambda+\mu\cdot p_{1}(t)\end{flalign}$$

시간이 많이 흘러서 더 이상 시간에 따른 확률 변화가 없어진다면 도함수 값이 0이 되고, 확률값이 상수 $\Pi$가 되어 계산이 가능해진다   

$$\begin{flalign}0&=-\Pi_k (\lambda +\mu) +\lambda \Pi_{k-1}+\mu \Pi_{k+1}\\ \lambda (\Pi_k -\Pi_{k-1})&=\mu (\Pi_{k+1}-\Pi_k)\\ (\Pi_k -\Pi_{k-1})\cdot \frac{\lambda}{\mu}&=(\Pi_{k+1}-\Pi_k)\\\\ 0&=-\lambda \Pi_0+\mu \Pi_1\\ \lambda\Pi_0 &=\mu\Pi_1 \\\\ \Pi_k&= (\Pi_k -\Pi_{k-1})+(\Pi_{k-1}-\Pi_{k-2})+\dots +(\Pi_1-\Pi_0)+\Pi_0\\ &=(\sum_{i=1}^{k}{(\Pi_1-\Pi_0)\cdot(\frac{\lambda}{\mu})^{i-1}})+\Pi_0\\ &= \frac{(\Pi_1-\Pi_0)(1-(\frac{\lambda}{\mu})^k)}{1-\frac{\lambda}{\mu}}+\Pi_0\\&=\Pi_0 \left( \frac{\lambda}{\mu} \right)^k\\\\ \sum^\infty_{i=0}\Pi_i&=1\\ \frac{\Pi_0}{1-\frac{\lambda}{\mu}}&=1\\ \Pi_0&=1-\frac{\lambda}{\mu}\end{flalign}$$

memoryless(poisson) 외에도 deterministic(constant), general한 분포도 가능하다. (e.g. M/D/1, M/G/1)   


## TOC

* 기업의 목적은 돈을 버는 것
* 기업의 입장에서 중요한 지표 : 순이익, 투자수익률, 현금유동성
* 근로자의 입장에서 중요한 지표 : 현금창출률, 재고, 운영비
* 공장의 모든 일은 "종속적 사건"으로 되어 있고 "통계적 변인"이 작용한다
* 종속적 사건 및 통계적 변인에 의해 목표 생산량을 수요에 맞추면 기업은 망하게 된다
* 자원은 "병목 자원"과 "비병목 자원"으로 나눌 수 있다
* 기업의 생산량은 가장 병목이 많이 발생하는 자원의 처리량에 의해 결정된다
* lead time은 setup time, process time, queue time(병목 자원 앞에서 기다리는 시간), wait time(다음 공정으로 이동하거나 다른 부품을 기다리는 시간)의 합으로 구성된다
* TOC에서는 병목 자원을 constraint으로 본다
* 1회 생산량을 줄이면 queue time과 wait time을 줄일 수 있고 전체 lead time도 줄어든다.

### terminologies

- production : supply를 사용하여 한정된 resources로 demand를 만족하기 위해 products를 생산하는 행위
	- resources : operator, machines
	- demand : customer가 요구하는 생산 수량이나 sojourn time
- planning : 시스템의 이익이 최대화되도록 하는 plan을 만드는 과정 (longer time horizon)
- scheduling :  한정된 resources로 planning level decision을 실현하기 위해서 '특정 시점'에서 supply로 product을 만들어 내는 행위
	- scheduling을 최적화하는 모델에서 planned demand는 objective function에 반영이 되고 supply는 WIP가 되며 resources는 constraints로 표현된다.  
- dispatch : 처리되길 기다리는 jobs 중에 다음 처리될 job을 지정하는 일  

- MRP(Material Requirements Planning, 자재 소요량 계획) : 상품의 수량과 납기를 충족하기 위해서 재고의 종류, 수량, 주문 시기를 결정하는 재고 관리 기법  
	- MPS, BOM, Inventory record를 바탕으로 계산함
		- MPS(Master Production Schedule) : 언제까지 얼마 생산해야 되는가?
		- BOM(Bill of Materials) : 상품 하나 만드는데 어떤 재료가 얼마나 필요한가?
		- Inventory record : 지금 현재 재고가 얼마나 있는가?
	- MRP는 자원 용량이 무한하다고 가정한다는 단점이 있음
	- MPS를 수립하고 MRP를 돌린 다음에 Scheduling 작업을 수행 -> feasible하면 dispatch
	- MRP에서 lot 주문량 결정 정책
		- L4L : 수요만큼 주문
		- FOQ(Fixed Order Quantity) : 고정된 양만큼 주문
		- EOQ(Economic Order Quantity) : 주문 비용과 재고 비용을 최소화하는 양만큼 주문 $$\begin{flalign}\text{Cost}(Q)&=\frac{D}{Q}S+\frac{Q}{2}H\\\frac{d\text{Cost}(Q)}{dQ}&=-\frac{DS}{Q^2}+\frac{H}{2}=0\\ Q&=\sqrt{\frac{2DS}{H}} \end{flalign}$$
			- D(demand) : 단위 기간 총 수요
			- S(setup cost) : 단위 1회 주문 비용
			- H(holding cost) : 연간 보관비용
		- POQ(Period Order Quantity) : 일정 기간 동안 수요를 합친 양만큼 주문
	- ROP(Reorder point) : 재주문점으로 안전재고 + 조달기간 동안 사용되는 양으로 구성됨
	- MPS 계산 원리 : 직전 기간의 내고가 max(예측량, 실제 주문량)보다 작으면 MPS에 들어가야 됨
- ERP(Enterprise Resource Planning, 전사적 자원 관리) : 생산, 물류뿐만 아니라 재무, 회계, 영업 등의 경영 활동 프로세스를 통합하여 자원을 최적화하는 통합 시스템  
- APS(Advanced Planning and Scheduling, 최적화 생산 계획 및 스케줄링) : 제약 조건을 실시간으로 반영하여 최적의 생산 planning과 scheduling을 돕는 의사결정 지원 시스템  
	- FCS(Finite Capacity Scheduler) + FRP(Finite Resource Planning) : resource가 유한하다는 것을 고려함
- MES(Manufacturing Execution System) : ERP에서 나온 생산 계획을 실행하고 WIP나 공정 데이터를 수집하는 시스템
- FDC(Fault Detection and Classification) : 센서 데이터를 모니터링해서 이상 유무를 판단하고 이를 MES에 전달하는 시스템

## Dispatching

- dispatching policy에 따른 production system의 분류
	- pull system : 현재의 정보를 바탕으로 의사 결정을 하는 시스템 (현재 상황이 이러하니 이렇게 한다)
		- control이 closed-loop 형식으로 현재 정보를 바탕으로 feed-back이 가능함
		- demand-driven
		- WIP의 상한이 존재함
		- e.g. Kanban, CONWIP, JIT
	- push system : 결정이 실현되는 시점에서 과거 정보를 바탕으로 의사 결정을 하는 시스템 (앞으로 이럴 것이니 이렇게 한다)
		- control이 open-loop 형식으로 feed-back 반영이 어려움
		- 상위 계획이나 MRP에서 내려온 schedule-driven
		- WIP의 상한이 없음
		- e.g. MRP
- APS는 hybrid(pull + push)의 성격을 띔


### dispatching rules

- FIFO(FCFS) : 선입선출
- SPT(Shortest Processing Time)
- Priority
- EDD(Earliest Due Date) : 납기가 빠른 제품 먼저
- MWKR(Most Work Remaining) : 작업물 수량이 가장 많은 것 먼저 처리
- LWKR(Least Work Remaining) : 작업물 수량이 가장 적은 것 먼저 처리
